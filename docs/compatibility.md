# 兼容性与验证边界

## 模型目录

CSwitch 保存第三方返回的模型编号并显示数量。Codex 的 `model_catalog_json` 是完整模型元数据格式，除了编号还要求工具类型、可见性、截断规则等字段。单独两个字段的模型目录会让 Codex 配置加载失败，因此现有用户目录设置按原值保留，供应商仅有编号时只更新 CSwitch 内的列表。完整的 Codex 模型选择集成仍需供应商提供可信的完整元数据，或 Codex 提供独立的模型编号列表接口。

当前配置、保存的配置和恢复备份引用的供应商模型目录会阻止对应旧代次清理，避免恢复配置后找不到文件。引用仍存在时，旧代次内的凭据也会保留。删除供应商遇到外部引用会显示路径，待引用解除后再删除。

## 协议转换

支持文本、网址或内联图片、函数工具、自定义文本工具、Chat Completions 结构化输出。未支持的内容、工具、跨请求服务端会话引用会明确报错，避免静默丢失。

Anthropic 请求要求调用方给出 `max_output_tokens`。CSwitch 不推断输出上限、上下文长度或思考预算。Anthropic 结构化输出、扩展思考映射、文件和音频、Responses compact、WebSocket 仍需专门实现与真实客户端验证；当前遇到这些请求会明确停止，而非伪造成功。

流式读取空闲超时为 120 秒，非流式响应和请求体上限为 32 MiB。回调登录尝试官方固定回调端口，端口占用时显示全部监听错误；新的随机回调端口需要官方 OAuth 客户端允许，故未自行添加。

## 进程与数据库

标准桌面安装自动退出。额外 CLI、IDE 或未知安装路径的 Codex 进程按进程号报错，由用户先关闭，避免误杀名字相同的其他程序。

同时检查 `.codex/state_5.sqlite`、`.codex/sqlite/state_5.sqlite` 以及 `.codex` 内明确配置的 `sqlite_home`。多个数据库存在时统一备份、更新和恢复所有这些数据库，避免靠数量或时间戳猜测哪个正在使用。

每次切换完整检查会话首行，只对差异执行写入。这保证旧的部分迁移状态也能被发现。空文件、截断文件、无效 JSON 会列出路径并保留，修复历史损坏后再切换。首行替换采用临时文件，预留复制和回滚空间，并检查正文是否在复制期间变化。

配置、认证和设置在写入前再次比较原值，恢复时也检查外部修改。这是冲突检测，不是对其他程序的强制文件锁；实际切换仍要求 Codex 停止写入，并避免同时手动编辑文件。

## 平台

HTTP 客户端使用系统根证书，支持环境变量代理和 Windows/macOS 系统代理；Linux 额外读取 GNOME 手动 HTTPS 代理。PAC、KDE 桌面代理、企业定制代理策略仍需专门适配；Linux 检测到 PAC 时明确提示通过 HTTPS_PROXY 指定固定代理。

CI 覆盖 Windows、macOS、Linux 的 Intel/x64 与 ARM 架构，并运行静态检查、单元测试及独立网关进程测试。本地 Windows 测试不等于其他平台已经实机验收。更旧 glibc、musl/Alpine 也没有包含在当前发行支持范围内。

macOS Developer ID 签名和公证需要 Apple 证书及仓库凭据；Windows 安装包签名需要 Windows 代码签名证书。代码修复和 CI 构建成功均不代表完成签名。发布前应确认签名、公证与目标系统安装测试。

## 凭据存储

Unix 快照目录与文件按私有权限创建；Windows 使用当前用户目录的继承权限。凭据和历史备份属于敏感文件，备份保留期间可能包含旧密钥。删除供应商会清理其快照，既有恢复备份依照十份保留策略轮换。
